# 給中央會員系統的需求說明：查詢「同中心會員名單」（指派小編用）

提出者：寰宇行動大學（hglobal1985/learn）　日期：2026-11-14　（業主已同意修改中央，由業主轉交中央維護者／中央 AI）

## 背景
行動大學要新增「小編」：各中心的**音控**（或會長）可以指派**同一個教育中心**的會員擔任小編，協助編輯該中心的課程與章節。小編身分只存在行動大學，中央不必記錄。

業主規定**不可用手動貼上會員 ID 的方式選人**，要讓音控直接從名單點選。中央目前只有「依會員 ID 查資料」（`POST /v1/apps/{app_id}/members/lookup`）與「查自己」（`GET /v1/eligibility/context`），沒有「列出某中心的會員」，所以需要新增。

## 需求：新增一支 API
- `GET /v1/eligibility/center-members?q=關鍵字&limit=20&cursor=...`
- **驗證：呼叫者本人的會員登入 Token**（與 `GET /v1/eligibility/context` 相同），不是服務 Token。這樣中央可以直接確認「是誰在查」。
- **誰可以查、查到哪個中心：**
  - 呼叫者在中央有 `sound`（音控）或 `president`（會長）職務，而且有**已審核**的教育中心 → 只回**他自己那個中心**的會員（不接受指定別的中心）。
  - `super_admin`、`secretary` → 可另帶 `center=<中心名稱>` 查任一中心（中心名稱以 `education_center` 詞庫為準）。
  - 其他人 → 403。
- **名單範圍：** 教育中心**已審核**且與呼叫者相同（以 `center.key` 正規化比對）的會員；停用、刪除的帳號不列入；不列呼叫者自己。
  - 是否只列「登入過此 App 的會員」由中央依既有隱私原則決定；業主希望**沒登入過行動大學的人也能被選到**，若中央同意請一併列出，並回傳 `signed_in_app` 讓 App 標示。
- **搜尋：** `q` 比對顯示名稱（可選擇同時比對真實姓名，由中央依隱私規則決定）；空白 `q` 回該中心第一頁。
- **分頁：** `limit` 預設 20、上限 50；`cursor` 取下一頁。
- **回傳（只給挑人需要的最少欄位）：**
  ```json
  {
    "center": { "key": "自強", "label": "自強" },
    "members": [
      { "member_id": "uuid", "display_name": "王小明", "avatar_url": "https://...或 null", "signed_in_app": true }
    ],
    "next_cursor": "...或 null"
  }
  ```
  不回傳信箱、電話、獎銜或其他 Amway 欄位。
- **稽核：** 每次查詢記錄（呼叫者、App、中心、筆數；不記內容）。
- 請同步更新 OpenAPI 文件與給 App 的串接指令（編新的版本號），並補測試：音控只看到自己中心、跨中心 403、無職務 403、未審核中心的會員不出現、分頁正常。

## 行動大學這邊的配合（中央完成後才做）
- 音控按「新增小編」→ 從這支 API 的名單點選（可打字搜尋）。
- 行動大學只存小編的 `member_id`、當下的顯示名稱、指派的中心與三種權限開關（新增／修改別人／刪除別人），不存中央回來的其他資料。
- 小編每次登入時，行動大學用他本人的 `GET /v1/eligibility/context` 確認中心仍相同；換了中心就自動失效。

## 不在此需求內
- 不在中央新增「小編」職務，也不寫入任何會員資料。
- 不開放修改中心、職務或獎銜。
