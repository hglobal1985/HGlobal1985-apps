# 請中央會員系統配合：登入永久保持（行動大學 2026-11-21）

業主要求：**會員在行動大學登入一次就永久有效，除非自己按「登出」**；並且共用會員中心的登入（在會員中心登入過，打開行動大學不用再登入）。

行動大學這端已完成（2026-11-21 上線，版本 02d86c5）：
- 網頁版登入憑證改存 localStorage（以前是 sessionStorage，關分頁就登出）；App 版本來就存 SecureStore。
- 多個分頁換發 refresh token 時跨分頁加鎖，同一時間只有一個分頁去換，不會拿已用過的 refresh token 再換一次。
- 換發失敗時，下次開頁面自動走 `/auth/sso/check`，會員中心還登入著就自動登回來。
- 已登入的人不再每開分頁都走 `/auth/sso/check`。

**剩下行動大學做不到、需要中央配合的部分**（請中央回覆目前的數值，並評估調整）：

1. **refresh token 的有效期限改成「滑動延長、沒有絕對上限」**：每次成功換發就重新計算期限（例如閒置 180 天以上才失效）；不要有「登入後滿 N 天一律失效」的絕對上限。請告知目前的閒置期限與絕對期限。
2. **refresh token 重複使用的寬限期**：同一張 refresh token 在剛換發後的短時間內（例如 60 秒）再被送來，回傳同一組新憑證，而不是判定盜用、撤銷整個登入。網路重送、手機切換網路、瀏覽器分頁競爭都會造成這種情況，現在一旦發生就會把會員整個登出。
3. **「這個瀏覽器已登入」的記憶（sso/adopt 的 cookie）改成長效持久 cookie**（Secure、HttpOnly、SameSite=Lax，例如 400 天、每次使用就延長），不要是關瀏覽器就消失的 session cookie。
4. **`/auth/sso/check` 也要認得「直接在會員中心網站登入」的會員**：會員在 id.hglobal1985.com 登入後，第一次打開行動大學，`sso/check` 就回 `sso_code`（不必先在行動大學登入一次、做過 adopt 才認得）。
5. **只有這些情況才讓登入失效**：會員自己按登出／登出所有裝置、帳號停用、會員中心偵測到確實的安全事件。其他情況（伺服器更新、金鑰輪替…）不要讓既有登入失效。

完成或有限制時，請回覆行動大學：目前的 refresh token 期限、寬限期做法、sso cookie 期限、第 4 點是否支援。
