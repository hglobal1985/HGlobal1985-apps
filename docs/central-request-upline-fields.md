# 給中央會員系統的需求說明：批次查詢會員的「上手白金、上手鑽石」（課程報名名單用）

提出者：寰宇行動大學（hglobal1985/HGlobal1985-apps）　日期：2026-11-20　（杜杜龍同意修改中央，由杜杜龍轉交中央維護者／中央 AI）

## 背景
行動大學新增課程「報名名單」：有審核權限的人（超級管理員、課程編輯者、審核人員）打開名單時，要看到每位報名學員的
**姓名、中心、上手白金、上手鑽石**，並可匯出 CSV。

「上手白金」「上手鑽石」是 Amway 會員資料。行動大學規定**不保存** Amway 資料（只准保存中心名稱），
所以希望**由中央提供，行動大學只在顯示當下讀取、不存入資料庫**。

行動大學已知中央有 `POST /v1/apps/{app_id}/members/lookup`（依會員 ID 查資料，欄位由中央「平台設定」勾選）。
行動大學目前不確定中央是否已有這兩個欄位、欄位叫什麼名稱，請中央確認後回覆。

## 請中央確認／提供

1. **這兩個欄位在中央是否存在？** 欄位代碼（例如 `upline_platinum`、`upline_diamond`）、型態（文字？會員 ID？）、
   是否有「待審核」狀態。若是會員 ID，請同時回傳該上手的顯示名稱，行動大學只顯示名稱。
2. **加入 lookup 的可選欄位：** 在 `POST /v1/apps/{app_id}/members/lookup` 的欄位清單新增
   `upline_platinum`、`upline_diamond`，並與其他欄位一樣由中央後台「平台設定」替行動大學勾選才會回傳
   （沒勾選回 403 `field_not_allowed`，與現有 `display_name` 一致）。
3. **批次：** 一次請求可帶最多 100 個 `member_id`（行動大學會分批呼叫，名單上限預計約 500 人以上）；
   回傳依請求順序，查不到的 ID 回 `null`，不要整批失敗。
4. **隱私：** 只回行動大學平台設定勾選的欄位；不回信箱、電話、會員編號。已停用或刪除的帳號回 `null`。
5. **稽核：** 記錄呼叫的 App、筆數與欄位名稱（不記內容）。
6. **效能：** 請告知單次 100 筆的預期回應時間，以及對行動大學的呼叫頻率限制（例如每分鐘幾次），
   行動大學會依此做分頁與短時間快取（只放在 Worker 記憶體／Cache，不存資料庫）。
7. 請同步更新 OpenAPI 文件與給 App 的串接指令（編新的版本號），並補測試：批次、未勾選欄位 403、
   停用帳號回 null、超過 100 筆回 422。

## 行動大學這邊的配合（中央完成後才做）
- 報名名單頁每次載入「目前這一頁」（每頁 50 筆）的會員，才向中央讀取這兩欄；CSV 匯出時分批讀取。
- 不寫入 D1、不寫日誌；匯出會寫入稽核紀錄（誰、哪門課、幾筆，不含內容）。
- 中央尚未提供、或讀取失敗時，這兩欄顯示「未提供」，其他功能不受影響。

## 不在此需求內
- 不開放修改任何會員資料。
- 不新增任何職務或權限判斷：「誰能看名單」由行動大學自己決定。
