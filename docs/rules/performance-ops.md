# 杜杜龍規則：載入速度、部署、伺服器效能與維運

> 從 CLAUDE.md 原文搬來，內容一字未改（2026-11-22 瘦身）。動到這個領域的功能前請先讀；規則依時間順序，後面的條目常會「取代」前面的。

- **載入速度與程式整理（2026-11-21，杜杜龍授權夜間整理）**：
  ① **管理者專用的編輯工具「用到才下載」**：課程編輯（設定、章節、教材、區塊、EDM）、中心編輯面板、系列封面與「套用到全系列」、新增課程、時間軸、系列 EDM，一律從 `features/admin-parts.tsx` import（底下是 `lib/lazy-part.tsx` 的 `lazyPart`，全部經由同一包 `features/admin-bundle.ts`）；**不可**在一般頁面直接 import `course-edit/lessons`、`course-sections`、`material-sheet`、`admin/edm-manager` 等檔案，否則學員又要多下載約 200KB。新增管理者專用的大面板：在 `admin-bundle.ts` 與 `admin-parts.tsx` 各加一行。打包工具會把「被兩個以上按需下載包共用」的檔案搬回主程式，所以一定要經由同一包。驗證方式：`npx expo export --platform web` 後看 `__common-*.js` 大小（2026-11-21：836KB → 629KB）。
  ② **共用小元件搬到 `ui/`**：勾選框 `Check`（`ui/check.tsx`，也從 `@/ui` 匯出）、編輯清單的小方形按鈕 `IconButton`（`ui/icon-button.tsx`，外觀 28 但觸控範圍 44）、數字調整列 `Stepper`（`ui/stepper.tsx`）。不要再從 `course-sections`、`lessons`、`app/admin/storage` 匯入它們。
  ③ **圖示字型自動瘦身**：部署打包時（`apps/launch/scripts/embed-static.mjs` → `subset-icons.mjs`）掃描 App 原始碼裡用到的 Ionicons 名稱，只保留那些圖示（壓縮後 185KB → 41KB）。圖示名稱一律寫成字串（`name="play"`、`ok ? "a" : "b"`），**不可用程式拼出圖示名稱**（例如 `` `${x}-outline` ``），否則那個圖示會被瘦身掉變空白。
  ④ **QR Code 產生器、App 專用的檔案分享工具**改為用到才載入（`invite-button.tsx`、`lib/share.ts`）。
  ⑤ **伺服器查資料庫要「同時查」**：每次資料庫來回在台灣約 30～70ms；彼此不相依的查詢一律放進同一個 `Promise.all`，寫入用 `db.batch` 一次送出。課程頁 `courseDetail` 已從 12 趟減為 4 趟、`/me` 4→3、`/courses` 少 1 趟。新增查詢先加進現有的 `Promise.all`，不要在後面再 `await` 一次。
  ⑥ **中央查詢共用的錯誤**：`central.ts` 的 `cached()` 讓同一人同時的多個請求共用一次中央查詢；先發起的請求若被瀏覽器取消，其他請求改自己重查（2026-11-20 晚上正式站因此偶發 500）。`loadSession` 的名稱頭像查詢失敗不會讓請求失敗。
  ⑧ **開網站不重複抓資料**：共用登入檢查（`webSsoCheck`，每個分頁每 5 分鐘一次，會整頁跳到會員中心再回來）即將發生時，不做開機預先抓取（`webSsoCheckDue()`）；`cachedGet` 一般開頁面會共用「還在下載中的預先抓取」，不再重送。`useApi(null)`（訪客、沒權限）回報「不是讀取中」。訪客不送功能徽章回報（`trackFeature` 由 `setFeatureTrackSignedIn` 控制）、不讀中央審核清單。
  ⑦ 已刪除的殘留：`lib/tablet-scale.ts`（viewport 放大已停用，鎖定 1 倍改直接寫在 `index.html`，常數在 `lib/no-page-zoom.ts` 的 `VIEWPORT`）、`theme/layout.ts` 的 `textScale`、後端 `convert-to-list` API、多個沒有被呼叫的函式與匯入。
- **舊網頁切頁空白的自動恢復（杜杜龍 2026-11-22 回報：久沒用再點通知整頁空白約 10 秒）**：每個頁面（路由）是獨立的程式檔（`/_expo/static/js/…-雜湊.js`），網站每次更新檔名都會換；很久沒重新整理的舊網頁切到沒載入過的頁面，會因檔案已不存在（404）而載入失敗、畫面空白。`lib/error-report.ts` 的 `recoverFromStaleChunks()`：偵測到頁面程式檔載入失敗（script 錯誤事件，或 Promise 錯誤訊息符合 `CHUNK_FAIL`）就記錄 `chunk-load` 錯誤並自動重新載入最新版（2 分鐘內最多一次，避免無限重新載入）。每週錯誤檢查時看到 `chunk-load` 回報，代表這個機制有被觸發。若使用者仍回報久沒用會空白，先查是不是別的原因（例如手機瀏覽器凍結分頁後的網路延遲）。
- **使用統計（管理員 > 設定 > 使用統計，杜杜龍 2026-11-22）**：`/admin/usage`（有「統計分析」權限的人才看得到；入口在設定頁管理區「使用統計」，頁面 `app/admin/usage.tsx`）。匿名彙總表 `usage_stats`（migration 0113：台灣日期＋小時＋裝置 mobile／tablet／desktop＋系統 ios／android／other＋項目 visit／card_course／card_series／card_center＋卡片識別＋次數；不存會員編號與 IP）。App 端 `lib/usage.ts`：`installVisitTracking`（`_layout.tsx`，開啟記一次，背景超過 30 分鐘再回來再記）、`trackUsage`（首頁的系列卡／單張課程卡在 `series-tile.tsx` 的 `open`，中心卡在 `center-tile.tsx`；**中心頁內的卡不算**）；`POST /usage` 訪客也可、同一 IP 每分鐘最多 60 筆、格式不合就略過。頁面可選「列」「欄」兩個維度（裝置、系統、時段、每小時、日期、統計項目、卡片）做交叉表，並可篩選裝置、系統、時段、期間（7／30／90 天）；卡片名稱：課程用編號換標題、系列與中心用名稱（改名後會分開計）。**資料從 2026/11/22 起累計**。
- **使用統計頁改「點問題看答案」（杜杜龍 2026-11-22，從 5 種操作方式選定 E）**：`app/admin/usage.tsx` 最上面是 9 個現成問題（裝置比例、iOS／Android、哪個時段最多人、iPhone 用戶幾點看、手機和電腦時段比較表、哪種卡／哪張卡最多人點、平板最常點的系列卡、這週比上週），一次展開一題，每題＝一組固定查詢＋一句白話答案＋長條或表格；新增問題只要在 `QUESTIONS` 加一筆。最下面「自己組合（進階）」＝原本自選列、欄、篩選的交叉表（`Custom`）。後端 `/admin/usage` 不變。
- **分頁程式檔預先載入，避免點通知／課程／學習中／設定第一次空白（杜杜龍 2026-11-22 回報：進通知常整頁空白，重進第二次才正常）**：網頁版每個頁面是獨立程式檔（見上一條），底部分頁第一次點進去才下載，手機網路慢時畫面整頁空白（沒有任何讀取畫面）；第二次因為已下載所以正常。`app/_layout.tsx` 的 `warmTabChunks()`：網頁版開站 2.5 秒後用 `router.prefetch` 把 `/notices`、`/courses`、`/learning`、`/me` 的程式檔先載好（不切換畫面、不抓資料，已用 Playwright 驗證只多下載四個檔案、網址不變）。新增底部分頁時要把它加進這個清單。
- **使用統計排除管理員（杜杜龍本人）操作（杜杜龍 2026-11-23）**：杜杜龍自己的操作（電腦、手機、平板、未登入、無痕、切換測試帳號、超級管理員）預設不列入使用統計；統計頁最上方勾「包含管理員操作」（預設未勾）才算進來。判斷分三層，任一符合就記成 `admin=1`（`usage_stats.admin`，migration 0114，舊資料已清掉重來）：① 這次請求是管理員帳號（`role=admin` 或 `super_admin`）；② 裝置記號：管理員在該瀏覽器／手機登入過，App 存 `learn.usage.owner`，之後回報都帶 `owner:1`（`lib/usage.ts` 的 `markOwnerDevice`，由 `state/session.tsx` 在管理員登入時呼叫）；③ 網路位置：管理員用過的網路存成加密比對碼（`usage_owner_nets`，SHA-256 前 12 bytes，IPv6 只看前 64 位元，不存原始 IP），30 天沒再用管理員登入就失效，用來認出「同網路、未登入或無痕」的本人。杜杜龍同意此做法（家中網路只有本人使用）；若本人改在多人共用網路（中心 Wi-Fi）操作，同網路的一般會員也會被排除，那時要重新評估第 ③ 層。查詢 API：`/admin/usage?...&admin=1`＝含管理員。
- **Cloudflare 帳號方案（杜杜龍 2026-11-26 告知）**：一直是 Workers 付費方案（US$5／月），不是免費方案。所以 AI 辨識超過每日免費額度的部分可以直接付費計算（單價見 `ai-models.ts`），評估費用時不必再問杜杜龍「是不是付費方案」；要一次跑完大量辨識時，只要到 設定 › AI 模型 關掉「僅用免費額度」與每日上限即可。
- **使用統計加「相簿操作習慣」（杜杜龍 2026-11-26）**：新增統計項目 album_open／album_folder／album_photo／album_search／album_sort／album_info／album_share／album_download／album_move（`usage.ts` USAGE_KINDS；target 只記操作種類或類別名稱，不記搜尋內容、不記會員）。埋點：`lightbox-library.tsx`（打開、資料夾、搜尋、排序、移動）、`edm-viewer.tsx`（看單張、資訊、分享、下載）、`lightbox-grid.tsx`（複選分享／下載）、`block-album.tsx`（移動）。統計頁（admin/usage.tsx）加相簿統計項目、快速看「相簿操作」與 10 個相簿常見問題。
- **使用統計「本人裝置」登記＝裝置特徵＋網路位置兩個都符合（杜杜龍 2026-11-26：這台 iPad Air 的操作一律算本人，即使無痕、沒登入；後來要求改掉「只比對同裝置特徵」的粗暴做法）**：使用統計頁最上方（只有超級管理員）「本人裝置」卡：在要算本人的裝置上按「登記這台裝置與目前網路」，存「裝置特徵」（螢幕短邊x長邊@像素比:系統:類型，例 `820x1180@2:ios:tablet`，`lib/usage.ts` 的 `deviceFingerprint`）加「目前網路的比對碼」（`netHash`，SHA-256 前 12 bytes、IPv6 只看前 64 位元，不存原始 IP）到 `ui_settings` 的 `usage_owner_devices`（`{fp,label,at,nets[]}`，每台最多 5 個網路，可移除）。`POST /usage` 帶 `fp`，後端 `isOwnerDevice(db, fp, ip)` **特徵相同且網路是登記過的才算本人**，記成 `admin=1`（第 ④ 層；與帳號、裝置記號、自動學習的管理員網路並列），統計預設不含、勾「包含管理員操作」才列入。**瀏覽器拿不到網卡（MAC）位址**，無痕模式也沒有可持久的識別碼，所以用這個組合：別人的同型號裝置在不同網路不會誤認，別人在同網路但不同型號也不會誤認。限制：換到沒登記過的網路（手機熱點、別的 Wi-Fi）認不出，要在那個網路再登記一次；登記的是多人共用 Wi-Fi 時，同網路同型號的別人裝置仍可能被誤認；登記前的舊資料不回頭改標記。API：`GET／POST /admin/usage/devices`、`POST /admin/usage/devices/remove`（超級管理員）。（先前只比對裝置特徵的登記沒有網路資料，需要重新登記一次。）
- **GitHub 自動部署（杜杜龍 2026-11-27）**：`.github/workflows/deploy-learn.yml`、`deploy-check.yml`：合併進 main 且相關檔案有改，就由 GitHub 執行同一個安全部署（`DEPLOY_CI=1`：main 在部署途中又有新合併就交給下一次；線上已是同一版就略過）。同一款 App 同時只跑一個部署、後來的排隊。需要 GitHub Secret `CLOUDFLARE_API_TOKEN`。**目前狀態：等杜杜龍設定金鑰（未啟用）**——未啟用時作業只顯示提醒，AI 照舊手動部署；杜杜龍設定好後把這行改成「已啟用」，之後 AI 合併後不再手動部署，改看 Actions 的部署結果。
  - 杜杜龍要做的設定（一次性）：①Cloudflare 後台 › 右上頭像 › 我的設定檔 › API 權杖 › 建立權杖 › 範本「編輯 Cloudflare Workers」，帳號資源選「寰宇（hglobal1985）」帳號、區域資源選 hglobal1985.com，另加權限「D1 編輯」，建立後複製權杖。②GitHub learn 專案 › Settings › Secrets and variables › Actions › New repository secret，名稱 `CLOUDFLARE_API_TOKEN`、值貼上權杖。③GitHub learn 專案 › Settings › General › Pull Requests：勾「Allow auto-merge」與「Automatically delete head branches」。④Settings › Branches（或 Rules）› 新增 main 的保護規則：必須透過 PR、必須通過 `checks` 檢查。
- **分支清理（杜杜龍 2026-11-27）**：`.github/workflows/cleanup-branches.yml` 每週一自動刪除「內容已在 main、3 天沒動、沒開 PR」的分支；手動執行時可勾「全部清除」（除了 main 與還開著的 PR 全刪，杜杜龍確認所有功能都已上線時才用）。
- **migration 編號檢查**：自動檢查（checks.yml）會跑 `packages/server-shared/deploy/check-migrations.mjs`，每款 App 的 migration 編號重複或檔名格式不對就擋下。已套用的歷史撞號（launch 0088）列在 `HISTORICAL` 放行，不可改它的檔名。
