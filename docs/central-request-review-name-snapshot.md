# 給中央會員系統 AI 的指令：放寬「審核已處理紀錄可保存姓名與申請內容快照」

（業主 2026-11-22 指示，同日第二版：加入申請內容。請整段貼給負責 hglobal1985/id 的 AI。）

---

業主決定放寬寰宇行動大學（App 代號 learn）的一條規則，請依下列步驟處理，並遵守本 repo 的 `AGENTS.md`。**不需要新增任何 API，也不需要改任何程式**，只要更新串接指令與規範文字。

背景：行動大學的「獎銜、教育中心申請審核」（串接指令三、16）規定「App 不保存申請內容與名單」。但審核人員處理完之後，App 需要保留一份「已處理紀錄」（誰申請、誰審核、結果、時間）供日後查詢。紀錄裡若沒有申請人姓名，畫面只能顯示「會員」；若沒有申請內容（例如申請的獎銜、中心），紀錄就看不出處理了什麼，使用上很不方便。這個做法和三、11 的「交易紀錄存當時快照（姓名不跟著改）」是同一個精神。

請處理：

1. 在最新版串接指令 https://id.hglobal1985.com/handoff/learn 的「三、16 獎銜與中心的申請審核」App 端規則，把「不保存申請內容與名單」改成明文：
   - **允許** App 在「已處理紀錄」（審核完成後才留下，**待審中的申請不保存**）保存：
     - 申請人的**姓名快照**（處理當下中央回傳的 display_name），不跟著會員改名，不要求同步更新；
     - **申請內容快照**：申請欄位名稱（獎銜、教育中心、教育系統）、原本的值、申請的值、審核者修改後通過的值（獎銜存代碼或中文名稱皆可）。這屬於三、7 所說的 Amway 資料（獎銜），請在三、7 加註這一個明確例外：**僅限審核已處理紀錄，且只存「申請當下的快照」，不得再用它判斷資格或權限，資格一律即時向中央查詢**；
     - 處理結果（通過／不通過）、處理時間、審核人員的顯示名稱。
   - **仍然禁止**：保存會員編號（Amway 會員編號）、上手、資格查詢結果、整份待審名單、搜尋字，以及把姓名或申請內容寫進日誌、分析工具、錯誤回報（維持三、7 的限制）。
   - 收到 `member.deleted` 時，App 仍要把該會員在已處理紀錄裡的姓名與申請內容快照清除（改成空白），不用刪整筆紀錄。
2. 同步更新「已串接 App 的更新檢查清單」（第六節）的第 28 項：把「不保存申請與名單」改成「已處理紀錄可保存姓名與申請內容快照（僅供查詢、不得用來判斷資格）；不保存待審名單，姓名與申請內容不進日誌」。
3. 版本號往前加一（例如 2026-11-22.1），並在更新檢查清單新增一條，讓已串接的 App 知道這次只是「規則放寬、沒有新的程式要做」。
4. 改完回報業主：改了哪幾段文字（含三、7 的例外）、新的版本號。
