# 給中央會員系統 AI 的指令：放寬「審核紀錄可保存申請人姓名快照」

（業主 2026-11-22 指示。請整段貼給負責 hglobal1985/id 的 AI。）

---

業主決定放寬寰宇行動大學（App 代號 learn）的一條規則，請依下列步驟處理，並遵守本 repo 的 `AGENTS.md`。**不需要新增任何 API，也不需要改任何程式**，只要更新串接指令與規範文字。

背景：行動大學的「獎銜、教育中心申請審核」（串接指令三、16）規定「App 不保存申請內容與名單」。但審核人員處理完之後，App 需要保留一份「已處理紀錄」（誰申請、誰審核、結果、時間）供日後查詢。紀錄裡若沒有申請人姓名，畫面只能顯示「會員」，使用上很不方便。這個做法和三、11 的「交易紀錄存當時快照（姓名不跟著改）」是同一個精神。

請處理：

1. 在最新版串接指令 https://id.hglobal1985.com/handoff/learn 的「三、16 獎銜與中心的申請審核」App 端規則，把「不保存申請內容與名單」改成明文：
   - **允許** App 在「已處理紀錄」保存：申請人的**姓名快照**（處理當下中央回傳的 display_name）、申請欄位名稱、處理結果（通過／不通過）、處理時間、審核人員的顯示名稱。姓名快照不跟著會員改名，**不要求**同步更新。
   - **仍然禁止**：保存會員編號（member_id 以外的 Amway 會員編號）、整份待審名單、搜尋字，以及把姓名寫進日誌、分析工具、錯誤回報（維持三、7 的限制）。
   - 收到 `member.deleted` 時，App 仍要把該會員在紀錄裡的姓名快照清除（改成空白），不用刪整筆紀錄。
2. 同步更新「已串接 App 的更新檢查清單」（第六節）的第 28 項：把「不保存申請與名單」改成「已處理紀錄可保存申請人姓名快照；不保存待審名單與日誌」。
3. 版本號往前加一（例如 2026-11-22.1），並在更新檢查清單新增一條，讓已串接的 App 知道這次只是「規則放寬、沒有新的程式要做」。
4. 改完回報業主：改了哪幾段文字、新的版本號。
