# 給中央會員 AI 的指令：Amway 三欄順序改為「獎銜 > 系統 > 中心」（業主 2026-11-23 指示，請貼給中央會員那邊的 AI）

業主決定調整 Amway 資料三個欄位的**順序與相依規則**。中央會員是這三個欄位的正本，請中央先改、更新串接指令（`https://id.hglobal1985.com/handoff/learn`）與版本號，所有已串接的 App 再跟進。**行動大學的畫面已先照新規則改好（見下方「行動大學目前做法」），但儲存時仍會被中央舊規則擋下，需要中央這邊修改才完整生效。**

## 新規則
1. **順序**：畫面與欄位定義一律 **獎銜 → 直銷商培訓系統 → 地區教育中心**（`GET /v1/amway/field-definitions` 的欄位順序、中央會員自己的編輯頁、名字旁方框的相關說明都請同步）。
2. **獎銜一律可以選／可以送出，與系統、中心完全無關**。請刪除目前的限制：`PUT /v1/me/amway/fields/rank` 在系統或中心還沒有值時回 422 `invalid_field`（reason `system_center_required`）。
3. **中心只有在「系統 = 寰宇」時才能選**：
   - 系統是寰宇（`education_system` 屬於寰宇系統清單）→ 中心可從清單選擇或勾「無」。
   - 系統不是寰宇（其他系統、「無」、沒填）→ 中心不可選；請接受並視為已填值 `"無"`（App 會自動送 `"無"`），不審核、不顯示方框。
   - 請在後端驗證：非寰宇系統卻送了非「無」的中心，回 422（建議 reason `center_requires_hglobal`），避免各 App 各自判斷不一致。
4. **必填**：勾選「我是 Amway 會員」後三欄仍都必填（系統、中心可用「無」，中心在非寰宇系統時自動為「無」即視為已填）。
5. **審核規則不變**：「寰宇＋同時填了地區教育中心」時，中心與獎銜才需審核（獎銜不再被系統／中心的填寫順序卡住，但審核判斷仍看目前系統與中心的值）。

## 請同步更新
- 串接指令「五、會員資料」相關段落（尤其「獎銜要等系統與中心都有值…422 system_center_required」那一句改寫）與「名字旁的方框」說明（若順序要跟著改請一併說明）。
- 版本號加一，並在「六、已串接 App 的更新檢查清單」寫明：各 App 的資料頁欄位順序改為獎銜、系統、中心；中心在系統非寰宇時送 "無" 並停用。
- 業主已確認這是**中央先改、App 跟進**的流程；行動大學收到新版串接指令後會把 `central.ts` 的 `INTEGRATED_VERSION` 改成新版本。

## 行動大學目前做法（中央改完前的過渡）
- 畫面順序：獎銜 | 系統 | 中心（`apps/mobile/src/features/profile-prompt.tsx`）；獎銜永遠可選；系統選非寰宇時中心自動填「無」並停用，換回寰宇再清空讓會員選。
- 儲存順序仍是系統 → 中心 → 獎銜。若會員在系統與中心都還沒有值時只選獎銜，中央舊規則會回 422，畫面會顯示中央的錯誤訊息（中央改完後即消失）。
